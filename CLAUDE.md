## Commands

```bash
npm install        # node_modules is not committed; run this first
npm run dev        # dev server at http://localhost:3000
npm run build      # production build (also type-checks)
npm run lint       # eslint (flat config, next/core-web-vitals + next/typescript)
npx tsc --noEmit   # type-check only
npm test           # node:test unit tests in tests/**/*.test.ts (single file: node --test tests/school-match.test.ts)
```

Tests use Node's built-in runner with native TypeScript stripping (Node 24), so test files import with relative `.ts` paths and can only cover pure `lib/` code that has no runtime `@/` imports (type-only `@/` imports are fine). Per `AGENTS.md`, this is Next.js 16 with breaking changes from older versions — read the relevant guide in `node_modules/next/dist/docs/` (available after `npm install`) before writing Next-specific code. Note `app/layout.tsx` already uses the global `LayoutProps<"/">` helper type rather than an imported one.

## What this is

"DuHoc24 — Cổng Tiếp Nhận Hồ Sơ Du Học": a study-abroad application intake site, built as a teaching template for a 6-week course (README.md is in Vietnamese and holds the week-by-week roadmap). **Current state: Week 1 UI plus the Week 2 Gemini chatbot.** No database or auth yet; `.env.example` lists the variables later weeks (Supabase, magic-link login) will need. `GEMINI_API_KEY` is read from `.env` (git-ignored) by `app/api/chat/route.ts`. UI copy is Vietnamese (`<html lang="vi">`).

## Architecture

- **Next.js App Router**, React 19, TypeScript strict, Tailwind CSS v4 (CSS-first config in `app/globals.css`, no `tailwind.config`; PostCSS via `@tailwindcss/postcss`). Path alias `@/*` → repo root.
- **Routes** (`app/`): `/` landing (hero, quote form, highlights, chat widget), `/portal` student document portal, `/admin/*` (requests, schools, profiles, conversations; `/admin` redirects to `/admin/requests`). `app/admin/layout.tsx` supplies the sidebar shell. `/login` is deliberately not built yet (Week 6).
- **All data is hard-coded in `lib/mock-data.ts`**: types (`DocStatus`, `RequestStatus`, `ServicePackage`, `School`, `AdmissionRequest`, `StudentProfile`, …) and arrays (`schools`, `servicePackages`, `admissionRequests`, `studentProfiles`, `currentStudent`). Pages and components import directly from it. When wiring a real backend, this file is the seam to replace — keep the exported types as the contract.
- **Status values are snake_case Vietnamese keys** (`cho_duyet`, `da_duyet`, `tu_choi`, `chua_nop`, `dang_xu_ly`, `hop_le`, `can_nop_lai`). `components/status-badge.tsx` maps them to label/tone/icon (`docStatusMeta`, `requestStatusMeta`); add new statuses there as well as in the type.
- **Server vs client components**: pages are server components. Only interactive pieces carry `"use client"` — `components/site-header.tsx`, `components/admin/sidebar.tsx`, `components/landing/quote-form.tsx`, `components/landing/chat-widget.tsx`, and the Base UI-backed primitives in `components/ui/`. The quote form is static UI (local state only, no submission).
- **Chatbot**: `components/landing/chat-widget.tsx` POSTs the conversation to `app/api/chat/route.ts`, which calls Gemini (`gemini-3.5-flash-lite`, REST via `fetch`, no SDK) server-side. The model and its knowledge live in `lib/chat-knowledge.ts`: the system instruction restricts answers to the fixed Q&A set there and falls back to "leave your question/contact in the quote form" otherwise. To change what the bot can say, edit the Q&A in that file only. **Conversations are persisted in Supabase** (tables `conversations` + `messages`): the route (`POST`/`GET /api/chat`) stores and reads them via `lib/chat-store.ts`, using `lib/supabase-server.ts` (server-only client with `SUPABASE_SECRET_KEY`, bypasses RLS). The browser sends only the new message text and holds no history of its own; the conversation is identified by an httpOnly `chat_cid` cookie (random uuid). Both tables have RLS enabled with **no policies** and all grants revoked from `anon`/`authenticated` — keep it that way: never query them with the publishable key or from client code, and never prefix the secret key with `NEXT_PUBLIC_`. Schema changes go through Supabase migrations (project `xu ly ho so`). `/admin/conversations` (list) and `/admin/conversations/[id]` (messages) are server components reading real data via `listConversations`/`getConversation` in `lib/chat-store.ts` (`force-dynamic`); both have a delete button (`components/admin/delete-conversation-button.tsx` → server action in `app/admin/conversations/actions.ts`, messages go with it via `on delete cascade`). **`/admin` has no authentication yet (Week 6)**, so these pages expose private customer chats — and the delete action is callable by anyone — to anyone who can reach the URL — add auth before deploying.
- **Lead extraction**: on `/admin/conversations/[id]`, the "Trích xuất lead" button (`components/admin/extract-lead-button.tsx` → `extractLeadAction` in `app/admin/conversations/actions.ts`) sends the transcript to Gemini (`gemini-3.1-flash-lite`, JSON `responseSchema`, `lib/lead-extractor.ts`) and upserts one row per conversation into Supabase `leads` (`lib/lead-store.ts`): name, email, phone, study country, degree level, major, availability, wants_consultation, note, quality (`good`/`ok`/`spam`). Extraction is on demand, not automatic; the card (`components/admin/lead-card.tsx`) warns when new messages arrived after the last run, and the list shows the quality badge. The transcript is untrusted user text — the prompt treats it as data and the output is validated/clamped in `parseLead` before saving. `leads` has the same lock-down (RLS, no policies, no `anon`/`authenticated` grants) and cascades on conversation delete.
- **Reference schools (public data)**: Supabase table `schools` (name, country, `min_gpa`, `min_ielts`) — the opposite of the private tables: RLS has a `select` policy for `anon`/`authenticated`, but `anon` has no insert/update/delete grants, so only the server secret key can write. `lib/school-store.ts` (`listSchools`) reads it through `lib/supabase-public.ts` (publishable key, no secret) and feeds `/admin/schools` (`force-dynamic`). The mock `schools` array in `lib/mock-data.ts` is now only used by the mock `currentStudent.matches` on `/portal`; the "Thêm/Sửa/Xóa" buttons on `/admin/schools` are still inert UI.
- **Student portal (`/portal`)**: students upload 3 documents (transcript PDF, IELTS image, ID/passport image). `components/portal/document-features.tsx` (client) POSTs multipart to `app/api/portal/documents/route.ts`, which checks size (≤4MB, Vercel's body limit is ~4.5MB) and the real file type by magic bytes, sends the file inline to Gemini (`gemini-3.1-flash-lite`, JSON `responseSchema`, `lib/document-extractor.ts`), validates/clamps the output, and upserts into Supabase `student_documents` (one row per profile+type: status `hop_le`/`can_nop_lai`, reason, extracted jsonb). A wrong/unreadable document or a missing key field (name + GPA / overall / ID number) gives `can_nop_lai` with a Vietnamese reason. **Uploaded files themselves are not stored** — only the extracted fields (including the ID number). With no login yet, the profile is tied to the browser by an httpOnly `student_pid` cookie (`lib/student-store.ts`); `student_profiles`/`student_documents` have the same lock-down as the chat tables (RLS, no policies, no `anon`/`authenticated` grants). `/portal` is `force-dynamic` and shows all extracted fields (`components/portal/extracted-info.tsx`); the old mock school-match section and `currentStudent`/mock `schools` were removed (`components/portal/school-match.tsx` is unused for now). Dates are stored as `YYYY-MM-DD`; the GPA scale (10 vs 4) is not captured. Week 6 login should replace the cookie. The upload endpoint is anonymous and calls Gemini per upload — add rate limiting before deploying.
- **Scholarships (public data, data only so far)**: Supabase table `scholarships` (`school_id` → `schools`, `name`, `min_gpa` on the 10-point scale and/or `min_ielts`, both nullable but at least one set, and `support_type` = `percent_tuition` with `support_percent` 1–100, or `full` with `support_percent` null — enforced by check constraints). Same public-read/server-write policy as `schools`. No app code uses it yet; it is meant to be queried later (e.g. by the AI assistant) and eligibility should reuse the numeric rules in `lib/school-match.ts` (`gpaOnTenScale`), not an LLM judgement. Read it with `getSupabasePublic()` (join with `schools(name)` works through PostgREST).
- **School matching & `/schools`**: `lib/school-match.ts` compares a student's extracted scores with the `schools` table. School minimums are on a 10-point scale, so the transcript GPA is normalised first (`gpaOnTenScale`: uses the extracted `gpaScale`; no scale and >10 is treated as /100; no scale and ≤4.5 is ambiguous → not compared). The comparison only runs when the profile is complete and valid (`isProfileComplete`: all three documents `hop_le`) — otherwise `/portal` shows a notice and `/schools` hides the result column. It is plain numeric code with no AI involved, covered by `tests/school-match.test.ts`. Pass = GPA ≥ `min_gpa` **and** IELTS overall ≥ `min_ielts` (equality passes); verdicts `dat`/`chua_dat`/`thieu` (missing data, unless something already fails). `/portal` shows the result per school (`components/portal/school-match.tsx`); the public page `/schools` ("Điểm chuẩn trường" in the header nav) lists the benchmarks and adds a "Kết quả của bạn" column only when the browser's `student_pid` profile is complete. Page `<main>` needs `w-full`, otherwise inside the flex-column body it shrinks to fit a wide table and overflows on mobile.
- **Quote form**: `components/landing/quote-form.tsx` POSTs full name, country, degree level, package, email and phone to `app/api/quote/route.ts`, which validates them (`lib/quote.ts`; `isValidEmail` is shared with the form, which shows a Vietnamese inline error and blocks submit on a bad email), computes the price **server-side** from `lib/pricing.ts` (`PACKAGE_PRICES`: Cơ bản 15.000.000₫, Toàn diện 30.000.000₫ — the only place prices live; the package cards derive from it), inserts a row into Supabase `requests` (`full_name`, status `cho_duyet`) and returns the price for display. Same lock-down as the chat tables: RLS on, no policies, no grants for `anon`/`authenticated`. After saving, `lib/quote-webhook.ts` posts `full_name`, `email`, `package`, `quote_vnd` to the Make.com webhook in `QUOTE_WEBHOOK_URL` via `after()` (best effort: failures are only logged, never affect the customer's response).
- **Approving requests**: `/admin/requests` (`force-dynamic`) lists the real `requests` rows via `lib/request-store.ts`. The Duyệt button (`components/admin/approve-request-button.tsx`, with a confirm step → `approveRequestAction` in `app/admin/requests/actions.ts`) atomically flips `cho_duyet` → `da_duyet` (`claimRequestForApproval`, so a double click cannot fire twice), then awaits `sendApprovalWebhook` (`lib/approval-webhook.ts`) which posts `full_name`, `email`, `login_url` to the Make.com webhook in `APPROVAL_WEBHOOK_URL`. If the webhook fails the status is reverted to `cho_duyet` and the admin sees an error, so a request is only "approved" once the link was handed to Make. `login_url` comes from `APPROVAL_LOGIN_URL` (currently a placeholder pointing at the not-yet-built `/login`; Week 6: change just this value, Make needs no change). The Từ chối button (`components/admin/reject-request-button.tsx`, confirm step → `rejectRequestAction`) **permanently deletes** the row (`deletePendingRequest`, only while still `cho_duyet`, so a just-approved request is never deleted); nothing is sent to Make and `tu_choi` is never written. Webhook URLs live in `.env` only (never commit them).
- **UI kit**: shadcn/ui with style `base-nova`, built on **Base UI** (`@base-ui/react`), *not* Radix — component APIs and props differ from typical shadcn examples. Config in `components.json` (icons: `lucide-react`; extra registry `@tailark-oss`). Add primitives with `npx shadcn add <name>` into `components/ui/`; use `cn()` from `lib/utils.ts` to merge classes. Theme tokens are CSS variables in `app/globals.css` (light theme only is used in practice). Font is Be Vietnam Pro via `next/font`, exposed as `--font-sans`.
- **Images**: `next.config.ts` only allows remote images from `images.unsplash.com`; add other hosts to `images.remotePatterns` before using them with `next/image`.
